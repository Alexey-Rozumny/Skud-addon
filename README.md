# Skud-addon

Аддон для автономных СКУД: удалённое открытие дверей по Wi-Fi, история событий,
аутентификация админ-панели и ротация базы.

## Стек

- FastAPI + Jinja2
- PostgreSQL 16 (отдельный контейнер)
- SQLAlchemy 2.x
- Argon2 для паролей, cookie-сессии, CSRF

## Запуск

```bash
cp .env.example .env
# отредактируйте .env: пароль БД, SECRET_KEY
docker compose up -d --build
```

- админ-панель: http://SERVER:8081
- панель пользователя: http://SERVER:8080/u/<token>

При первом запуске создаётся администратор из `ADMIN_USERNAME`/`ADMIN_PASSWORD`.
Если `ADMIN_PASSWORD` пустой — пароль генерируется и печатается в логах:

```bash
docker compose logs door-admin | grep -A2 "Создан администратор"
```

## Сброс пароля администратора (CLI)

```bash
docker compose exec door-admin python manage.py reset-password admin
# или с явным паролем:
docker compose exec door-admin python manage.py reset-password admin --password 'new-pass'

docker compose exec door-admin python manage.py create-admin operator
docker compose exec door-admin python manage.py list-admins
```

Сброс увеличивает `token_version`, поэтому все активные сессии становятся недействительными.

## API для ESP

Ключ устройства (`door secret`) создаётся вместе с дверью и показывается в админке.
Его нужно сохранить в настройках ESP (NVS для ESP32, EEPROM для ESP8266).

### Регистрация

ESP при старте и периодически (например, раз в 60 секунд) регистрируется на сервере.
В ответ приходит «кодовая фраза», без которой сервер не сможет отправить команду.

```
POST /api/register
X-Api-Key: <door_secret>
Content-Type: application/json

{"ip": "192.168.1.42", "door_open": false, "fw": "0.2"}
```

Ответ:

```json
{"status": "ok", "door_id": "a1b2c3d4", "phrase": "0f1e2d3c4b5a6978", "ttl": 86400, "pulse_ms": 2000}
```

### Команда открытия (сервер -> ESP)

```
POST http://<esp_ip>/pulse
X-Api-Key: <door_secret>
X-Phrase: <phrase>
```

ESP должен проверить оба заголовка. Фраза живёт `PHRASE_TTL_SECONDS` и продлевается
при регистрации; при смене секрета устройства выдаётся новая фраза.

### События геркона (ESP -> сервер)

```
POST /api/event
X-Api-Key: <door_secret>
Content-Type: application/json

{"open": true, "trigger": "local"}
```

`trigger`:

- `remote_pulse` — дверь открылась после импульса от сервера;
- `local` — открытие ключом/кнопкой изнутри;
- можно не передавать — сервер сам сопоставит событие с недавней командой открытия.

Сервер сам проставляет время события и связывает `door_opened` с командой, если она была.

## Прошивка ESP32-C3 Super Mini

Файл: `For-esp/esp32-c3-super-mini/esp32-c3-super-mini.ino`

Пины по умолчанию:

| Назначение | GPIO |
| --- | --- |
| Реле (импульс) | 1 |
| Дверной контакт | 2 |
| Кнопка сброса Wi-Fi (BOOT) | 9 |
| Встроенный светодиод | 8 |

Встроенный светодиод (GPIO8, active LOW): частое мигание — режим настройки Wi-Fi (AP),
медленное — штатная работа.

Геркон подключается к GND, настроен `INPUT_PULLUP`, открытие = `HIGH`.
Если у контакта другая логика — поменяйте `DOOR_OPEN_LEVEL`.

**Важно:** GPIO2 — strapping-пин ESP32-C3. При старте он не должен быть притянут
к GND, иначе плата может не загрузиться. Используйте нормально разомкнутый контакт
или внешнюю подтяжку к 3.3 В.

При первом включении контроллер поднимает открытую точку доступа `ESP32C3_Setup`
с адресом `http://192.168.4.1` — там вводятся SSID и пароль Wi-Fi. Портал работает
до сохранения настроек, после чего плата перезагружается и подключается к сети.
Повторно портал можно вызвать удержанием BOOT 5 секунд, полный сброс настроек — 10 секунд.

Если точки доступа нет:

- проверьте Serial на скорости 115200 — там будет `Starting config portal`, `AP IP`
  и IP после подключения;
- убедитесь, что GPIO2 не притянут к GND при старте;
- если в NVS остались старые Wi-Fi-настройки, очистите flash:
  `esptool.py erase_flash` или включите «Erase All Flash Before Sketch Upload»;
- `Reset reason: 11` (`ESP_RST_USB`) означает, что плату перезагружает USB-монитор
  через DTR/RTS. Закройте монитор или используйте `idf.py monitor --no-reset`.

Остальные настройки хранятся локально на контроллере и открываются по кнопке
с шестерёнкой в админ-панели: `http://<IP_ESP>/settings`.

- сервер (host/IP) и порт;
- секрет устройства;
- галочка «Использовать дверной контакт».

Если секрет уже задан, для сохранения нужно ввести текущий секрет. При выключенном
контакте события открытия/закрытия не отправляются, а сервер показывает состояние
«Неизвестно».

Библиотеки: только **ESP32 core**. WiFiManager и ArduinoJson не нужны.
Wi-Fi-портал реализован штатными `WiFi.h` + `WebServer.h`.
В Arduino IDE: плата **ESP32C3 Dev Module**, USB CDC On Boot — по необходимости.

Удержание кнопки **BOOT** (GPIO9) 5 секунд очищает Wi-Fi и перезапускает портал;
секрет, адрес сервера и настройка контакта при этом сохраняются.
Удержание 10 секунд делает полный сброс: Wi-Fi, сервер, секрет и настройка контакта.
GPIO9 — strapping-пин: не держите BOOT нажатой при включении/сбросе питания,
иначе плата уйдёт в режим загрузчика.

## Прошивка ESP8266

Файл: `For-esp/esp8266-skud/esp8266-skud.ino`

Пины по умолчанию (NodeMCU / Wemos D1 mini):

| Назначение | GPIO | Плата |
| --- | --- | --- |
| Реле (импульс) | 5 | D1 |
| Дверной контакт | 4 | D2 |
| Кнопка сброса Wi-Fi (FLASH) | 0 | D3 |
| Встроенный светодиод | 2 | D4 |

Светодиод active LOW: частое мигание — режим настройки Wi-Fi, медленное — штатная работа.
Геркон подключается к GND, настроен `INPUT_PULLUP`, открытие = `HIGH`.

Настройки хранятся в EEPROM, а не в NVS. При первом включении открывается точка доступа
`ESP8266_Setup` с адресом `http://192.168.4.1`; после сохранения Wi-Fi плата
перезагружается. Удержание FLASH 5 секунд очищает Wi-Fi и перезапускает портал,
10 секунд — полный сброс (Wi-Fi, сервер, секрет, настройка контакта).

`GPIO0` — strapping-пин: не держите FLASH нажатой при включении питания, иначе плата
уйдёт в режим загрузчика. `GPIO2` при старте должен быть HIGH. В Arduino IDE выбирайте
**LOLIN(WEMOS) D1 R2 & mini** или **NodeMCU 1.0 (ESP-12E Module)**.
Библиотеки: только ESP8266 core; WiFiManager и ArduinoJson не нужны.

## История и ротация

Каждое действие пишется в `events`: команды, открытия/закрытия геркона, регистрация устройства,
смена секрета. Команды и физические открытия связаны через `parent_event_id`.

Период хранения задаётся в админке или через `EVENTS_RETENTION_DAYS` (0 — хранить вечно).
Дополнительно можно ограничить число записей. Очистка выполняется фоновой задачей
раз в сутки под advisory-lock, поэтому контейнеры не мешают друг другу.

## Разработка

```bash
docker compose -f docker-compose.dev.yml up --build
```

Dev-стек использует отдельный проект `skud-dev`, свой контейнер БД и volume,
поэтому не смешивается с прод-данными.

- админка: http://localhost:8081
- пользователь: http://localhost:8080/u/<token>
- логи: `docker compose -f docker-compose.dev.yml logs -f door-admin`

Каталог проекта монтируется в `/app`:

- изменения `*.py` → uvicorn перезапускает сервис (`--reload`);
- изменения `templates/*.html` и `static/*` подхватываются без перезапуска.

Сбросить dev-базу и создать заново:

```bash
docker compose -f docker-compose.dev.yml down -v
```

Если одновременно запущен прод-стек, порты 8080/8081 заняты — остановите его
или поменяйте порты в dev-файле.

Первый пароль администратора печатается в логах (если `ADMIN_PASSWORD` пустой):

```bash
docker compose -f docker-compose.dev.yml logs door-admin | grep -A2 "Создан администратор"
```

Сбросить пароль в dev-БД:

```bash
docker compose -f docker-compose.dev.yml exec door-admin python manage.py reset-password admin
```
